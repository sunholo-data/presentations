The real problem

Ask three times, get three decks

Same prompt, no design system
Same prompt, using the slides skill

A deck is not eleven separate pictures. It is one thing, seen eleven times. If every slide looks a bit different, an AI‑built deck feels cheap. With no guidance, the model makes the average slide: a colour gradient, three boxes, a stock icon. It looks fine. Fine is the problem.

A skill is a folder of instructions for Claude Code. The first lines say what it is for. When your request matches, Claude opens the folder and follows it. The instructions are plain English, so you don’t need to code to write one.

Each part does a different job. Words guide the AI where taste matters. A template means it never starts from scratch. Checks catch the mistakes that must never reach the screen. You need all three.

1 · Rules in words

Write your taste down in plain words

excerpt · .claude/skills/presentation-slides/SKILL.md
Orange accent (#e73c17 dark / #bd3012 light) for emphasis, never overused.
Montserrat for all text, JetBrains Mono for code and data.
Subtle grid background at 60px intervals. Always support dark and light.
“Never overused” is not a number. It needs judgement, and the AI is good at that.

This is the brand guide you already have. The difference is that this reader actually follows it. You can write one for your own brand this afternoon. It works for any AI task, not only slides.

2 · Templates

Never start from a blank page

The template deck
the 16:9 slide shape
dark and light themes
keyboard and clicker keys
the presenter view and timer
the AI copies it,
then writes only
the new content
every new talk

The hard parts are solved once, in the template. The AI copies a deck that already works and changes only the content. That is faster, and it can’t forget the theme switch or the keyboard keys.

3 · Automatic checks

A check gives the same answer every time

The AI edits a slide
The check runs by itself
“Text is sized to the window, not the slide”
The AI fixes it
Pass

A check is a tiny program. Same file in, same answer out. You can’t talk it round.

Written rules get followed most of the time. That is not enough when you only see the mistake on stage. So the simple rules are checked by code, after every edit, with no human in the loop. My example: text sized to the browser window falls off the bottom on a projector. The check catches it every time.

This works for any job you give an AI, not only slides. Reports, emails and contracts all have taste, structure and hard rules. Two mistakes to avoid: don’t turn taste into a strict rule, and don’t trust words alone for a hard rule.
