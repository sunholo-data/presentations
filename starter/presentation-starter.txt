FOR THE PERSON USING THIS FILE
Attach this text file to your AI chat and send:

Follow the attached presentation guide and template. Create a six-slide HTML presentation about [topic] for [audience]. The audience should leave knowing [message]. Use these facts and sources: [paste your material]. Return one HTML file I can download and open in a browser.

Keep the same chat for revisions and ask for specific changes. If the AI cannot create a download, ask it for the complete HTML in one code block; save that as presentation.html using a plain-text editor. File creation and previews vary by product, account and workspace settings.

Open the finished HTML in a current browser. Use left/right arrows or the buttons to navigate, the theme button to change appearance, and D to toggle extra reading notes. Google Fonts and Font Awesome are loaded from their existing public CDNs; internet access gives the intended typography/icons. System font fallbacks are included. Avoid 3D models and other fetched local assets for this simple file-based workflow.

FOR THE AI - FOLLOW THIS WORKFLOW
This is a portable presentation guide, not a request to install software or change account settings. Treat the user's task and supplied source material as authoritative.

1. Establish the topic, audience, desired outcome, slide count and available facts. Use reasonable defaults where the brief is sufficient; ask only for information that materially changes the deck.
2. Read all of this guide and the complete template before writing. Use the template as the starting point. Return an HTML presentation, rather than converting it to PowerPoint, unless the user explicitly requests a different format.
3. Plan a clear argument. Give each slide one point and a useful title. Prefer a concrete visual, comparison or example over dense lists. Keep stage text short; add explanatory reading notes only where there is room.
4. Preserve the template's fixed 16:9 canvas, navigation, theme switching and detail toggle. Replace the sample content and add sections as needed. Number data-slide values consecutively from zero. The navigation calculates the count from the sections.
5. Use inline CSS and the existing inline JavaScript. Do not add build steps, packages, trackers, forms, external embeds or new external scripts. Do not add repo-relative logos, images or links that will break after download. Use images the user supplies; bundle them as data URLs when tools allow, or clearly explain any companion assets. Never invent a company logo or attributed quotation.
6. Produce one complete HTML file, ideally as a downloadable attachment. Do not return an outline alone. If file creation is unavailable, return the complete HTML in one code block and explain how to save it.
7. Validate what you can and report what actually ran. If tools are unavailable, do not claim to have run code, inspected a rendered page, or verified animations. Explain the remaining manual checks briefly.

DESIGN RULES
- Use the template's Sunholo-inspired palette: orange for emphasis, slate text, pale ground in light mode; dark navy ground and light text in dark mode. Keep orange selective.
- Use Montserrat with sans-serif fallbacks for prose and JetBrains Mono with monospace fallbacks for code/data. Preserve both themes' CSS variables.
- The design canvas is 16:9. .slides-viewport fits the available area; .slides-stage letterboxes the canvas. Slides are absolutely positioned inside that stage.
- All content sizing follows the stage. Use cqi (stage width), cqb (stage height), percentages or flex with min-height:0. Never use vh/vw or their variants for slide content, or calc(100vh - ...). Clamp text sizes carefully; minimum pixel sizes can still overflow small stages.
- Keep titles roughly 24-54px at normal laptop/projector scales, body 13-27px, and captions 10-17px, using stage-relative clamp expressions as in the template. Shorten copy before shrinking it into unreadable text.
- Preserve restrained entrance animations and slide transitions. Use motion to explain or reveal, rather than decorate every object.
- .detail is additional prose, hidden in stage mode and shown in guide mode with D. A slide must make sense without it. Check both modes.
- Use manual syntax highlighting for code if needed; avoid adding a library.
- Facts and quotes must come from supplied or accessible sources. Cite sources in the deck where useful. Mark missing evidence instead of filling gaps with invented claims.

VALIDATION
If a browser is available: open the file at 1920x1080 and a smaller/taller window; check arrow keys, nav buttons, first/last boundaries, theme switching, D, slide count, content positioning and overflow in both themes and both density modes. Check image loading and motion where relevant.
If Node.js and filesystem tools are available: extract the optional checker below to a temporary lint-slides.mjs file and run `node lint-slides.mjs presentation.html`. Do not install Node just to satisfy this guide. The checker catches forbidden CSS sizing units; it does not prove visual fit, accessibility, factual accuracy or successful animation playback. Browser checks are separate.
If execution is unavailable: review markup and paths, then state that automated/browser checks did not run. Ask the user to inspect the downloaded deck before presenting.

OPTIONAL CHECKER - FOR AN AI WITH NODE.JS EXECUTION
```javascript
#!/usr/bin/env node
// lint-slides.mjs - verify slide HTML doesn't smuggle viewport units into
// stage-relative content. See SKILL.md Right "Stage-safe sizing rules".
//
// HARD RULES (exit 2 with diagnostics on violation):
//   1. No vh / vw / dvh / dvw / svh / svw / lvh / lvw inside slide content,
//      except the single permitted line `#app{...;height:100vh}` which is
//      the legitimate top-level shell that fills the iframe/window.
//   2. No `calc(...100vh...)` / `calc(...100vw...)` anywhere - these
//      double-count chrome and overflow the letterboxed stage.
//
// SCOPE: Only files that contain `class="slide"` or `class="slides-stage"`
// are linted. Landing pages, playlist hubs (presenter.html, *.index.html),
// and any other regular HTML get a free pass - vw/vh on a normal responsive
// page is fine; this linter only protects the letterboxed slide canvas.
//
// TWO MODES:
//
//   CLI mode - audit existing files:
//     node lint-slides.mjs <file.html> [<file.html> ...]
//     node lint-slides.mjs                  # walk cwd for *.html
//
//   Hook mode - PostToolUse JSON via stdin (Write / Edit / MultiEdit):
//     echo '<json>' | node lint-slides.mjs
//   Lints only the strings the tool call is *introducing*, not pre-existing
//   content elsewhere in the file. So edits that don't touch the offending
//   CSS won't trip the hook just because old violations exist nearby.
//
// EXIT CODES:
//   0 = clean (or N/A - non-HTML, presenter shell, missing file)
//   2 = violations found; stderr contains a Claude-readable diagnostic.

import { readFileSync, readdirSync, statSync } from 'node:fs';
import { basename, join, relative, resolve } from 'node:path';

const VIEWPORT_UNIT  = /(\d+(?:\.\d+)?)(vh|vw|dvh|dvw|svh|svw|lvh|lvw)\b/g;
const CALC_VIEWPORT  = /calc\([^)]*\d+(?:\.\d+)?\s*v[hw]\b/gi;
const APP_SHELL_LINE = /#app\s*\{[^}]*height:\s*100vh/;
const SLIDE_DECK_MARKER = /class\s*=\s*["'][^"']*\bslide(s-stage)?\b/;

const RULE_HELP = {
  'viewport-unit':
    'Viewport units (vh/vw/dvh/dvw/svh/svw/lvh/lvw) measure the iframe/window, ' +
    'not the .slides-stage. Inside a non-16:9 window the stage is letterboxed ' +
    'and these units exceed it, so content overflows. Use cqb (1% of stage ' +
    'height) or cqi (1% of stage width) instead, or flex layout ' +
    '(flex:1; min-height:0).',
  'calc-with-viewport':
    'calc() with viewport units double-counts chrome that the stage already ' +
    'excludes via letterboxing, and overflows. Replace with cqb percentages or ' +
    'flex sizing.',
};

// -----------------------------------------------------------------------------
// Shared scanners

function scanText(text) {
  // Returns [{rule, match, line, snippet}] for raw text.
  // Line numbers are computed within `text` itself.
  const lines = text.split('\n');
  const out = [];

  VIEWPORT_UNIT.lastIndex = 0;
  let m;
  while ((m = VIEWPORT_UNIT.exec(text)) !== null) {
    const line = offsetToLine(text, m.index);
    const lineText = lines[line - 1] || '';
    if (APP_SHELL_LINE.test(lineText)) continue;
    out.push({
      rule: 'viewport-unit',
      match: m[0],
      line,
      snippet: lineText.trim().slice(0, 140),
    });
  }

  CALC_VIEWPORT.lastIndex = 0;
  while ((m = CALC_VIEWPORT.exec(text)) !== null) {
    const line = offsetToLine(text, m.index);
    out.push({
      rule: 'calc-with-viewport',
      match: m[0],
      line,
      snippet: (lines[line - 1] || '').trim().slice(0, 140),
    });
  }

  return out;
}

function offsetToLine(text, offset) {
  let line = 1;
  for (let i = 0; i < offset && i < text.length; i++) {
    if (text.charCodeAt(i) === 10) line++;
  }
  return line;
}

// -----------------------------------------------------------------------------
// CLI mode: scan whole HTML files, but only inside <style> blocks

function findStyleBlocks(html) {
  const blocks = [];
  const re = /<style[^>]*>([\s\S]*?)<\/style>/gi;
  let m;
  while ((m = re.exec(html)) !== null) {
    const start = m.index + m[0].indexOf('>') + 1;
    blocks.push({ start, content: m[1] });
  }
  return blocks;
}

function isSlideDeckText(text) {
  return SLIDE_DECK_MARKER.test(text);
}

function lintFile(filepath) {
  if (basename(filepath) === 'presenter.html') return [];

  let html;
  try { html = readFileSync(filepath, 'utf8'); }
  catch { return []; }

  // Skip files that aren't slide decks (landing pages, playlist hubs, etc.)
  if (!isSlideDeckText(html)) return [];

  const out = [];

  // 1. Scan <style>...</style> blocks
  for (const block of findStyleBlocks(html)) {
    const violations = scanText(block.content);
    for (const v of violations) {
      const absLine = offsetToLine(html, block.start) + v.line - 1;
      out.push({ file: filepath, ...v, line: absLine });
    }
  }

  // 2. Scan inline style="..." attributes (the hook mode catches these via
  //    snippet scan; CLI mode needs an explicit pass so audits agree).
  const styleAttr = /style\s*=\s*(["'])([^"']*)\1/gi;
  let m;
  while ((m = styleAttr.exec(html)) !== null) {
    const attrValue = m[2];
    const attrValueStart = m.index + m[0].indexOf(attrValue);
    const violations = scanText(attrValue);
    for (const v of violations) {
      const absLine = offsetToLine(html, attrValueStart);
      out.push({ file: filepath, ...v, line: absLine });
    }
  }

  return out;
}

function walkHtml(root) {
  const out = [];
  function walk(dir) {
    let entries;
    try { entries = readdirSync(dir, { withFileTypes: true }); }
    catch { return; }
    for (const e of entries) {
      if (e.name.startsWith('.') || e.name === 'node_modules') continue;
      const p = join(dir, e.name);
      if (e.isDirectory()) walk(p);
      else if (e.isFile() && e.name.endsWith('.html')) out.push(p);
    }
  }
  walk(root);
  return out;
}

// -----------------------------------------------------------------------------
// Hook mode: scan only the strings the tool call is introducing

function lintHookPayload(payload) {
  const ti = payload?.tool_input;
  if (!ti) return { violations: [], file: null };

  const fp = typeof ti.file_path === 'string' ? ti.file_path : null;
  if (!fp || !fp.endsWith('.html')) return { violations: [], file: null };
  if (basename(fp) === 'presenter.html') return { violations: [], file: fp };

  // Decide whether this file is a slide deck.
  //   - Write: the new content IS the file Right check the content for the marker
  //   - Edit / MultiEdit: the file already exists Right read it and check
  // If it's not a slide deck, skip - viewport units on landing pages are fine.
  const isWrite = typeof ti.content === 'string';
  let deckText = null;
  if (isWrite) {
    deckText = ti.content;
  } else {
    try { deckText = readFileSync(fp, 'utf8'); }
    catch { return { violations: [], file: fp }; }
  }
  if (!isSlideDeckText(deckText)) return { violations: [], file: fp };

  // Collect every new string this call introduces
  const snippets = [];
  if (isWrite) snippets.push({ label: 'content', text: ti.content });
  if (typeof ti.new_string === 'string') snippets.push({ label: 'new_string', text: ti.new_string });
  if (Array.isArray(ti.edits)) {
    ti.edits.forEach((e, i) => {
      if (e && typeof e.new_string === 'string') {
        snippets.push({ label: `edits[${i}].new_string`, text: e.new_string });
      }
    });
  }

  const violations = [];
  for (const s of snippets) {
    for (const v of scanText(s.text)) {
      violations.push({ file: fp, source: s.label, ...v });
    }
  }
  return { violations, file: fp };
}

// -----------------------------------------------------------------------------
// Output

function formatViolations(violations, mode) {
  const cwd = process.cwd();
  const out = [];
  out.push('');
  out.push('FAIL Slide stage-safe sizing violations:');
  out.push('');
  for (const v of violations) {
    const rel = v.file ? (relative(cwd, v.file) || v.file) : '(stdin)';
    const where = mode === 'hook'
      ? `${rel}  (in tool_input.${v.source}, snippet line ${v.line})`
      : `${rel}:${v.line}`;
    out.push(`  ${where}`);
    out.push(`    rule:  ${v.rule}  (matched: ${v.match})`);
    out.push(`    line:  ${v.snippet}`);
    out.push(`    fix:   ${RULE_HELP[v.rule]}`);
    out.push('');
  }
  out.push(`${violations.length} violation(s). See .claude/skills/presentation-slides/SKILL.md Right "Stage-safe sizing rules" for the full guide.`);
  out.push('');
  return out.join('\n');
}

// -----------------------------------------------------------------------------
// Entry

function readStdinSync() {
  try { return readFileSync(0, 'utf8'); }
  catch { return ''; }
}

function runCli(files) {
  const violations = [];
  for (const f of files) {
    if (!f.endsWith('.html')) continue;
    violations.push(...lintFile(f));
  }
  if (violations.length === 0) process.exit(0);
  process.stderr.write(formatViolations(violations, 'cli'));
  process.exit(2);
}

function main() {
  const args = process.argv.slice(2);

  // CLI mode with explicit file args - never reads stdin
  if (args.length > 0) {
    const files = args.map(a => resolve(a)).filter(p => {
      try { return statSync(p).isFile(); } catch { return false; }
    });
    runCli(files);
    return;
  }

  // No args. Try hook mode by reading stdin - but only if stdin isn't an
  // interactive TTY (which would block). `isTTY` is `true` for interactive
  // terminals and `undefined`/`false` for pipes, redirects, /dev/null, etc.
  let stdinData = '';
  if (process.stdin.isTTY !== true) {
    try { stdinData = readStdinSync(); } catch { stdinData = ''; }
  }

  if (stdinData.trim()) {
    try {
      const payload = JSON.parse(stdinData);
      if (payload && payload.tool_input) {
        const { violations } = lintHookPayload(payload);
        if (violations.length === 0) process.exit(0);
        process.stderr.write(formatViolations(violations, 'hook'));
        process.exit(2);
      }
    } catch {
      // not JSON - fall through to walk mode
    }
  }

  // Default: walk cwd for HTML files
  runCli(walkHtml(process.cwd()));
}

main();
```
